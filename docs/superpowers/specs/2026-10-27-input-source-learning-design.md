# 入力ソース自動割り当て学習 設計案

## 目的

欄ごとに入力開始時の入力ソースを記録し、よく使われるソースを自動割り当て候補として提示する。誤ったルールの自動登録を避けるため、候補はクイック画面で利用者が承認した後に登録する。

## ゴール

- 同じアプリ内でも入力欄ごとに別々の傾向を学習する。
- 利用傾向が十分に偏った場合だけ候補を提示する。
- 入力内容や欄のラベルを永続化せず、学習データは端末内に保存する。
- 利用者が学習履歴をリセットできる。
- 利用者が設定で学習を有効にした後だけ記録を始める。

## 対象外

- 利用者の承認なしに入力ソースルールを登録すること。
- 学習機能が無効な状態で観測・記録すること。
- 入力文字列、削除キー数、欄のラベルの記録。
- 安定して識別できない入力欄の推測・アプリ単位への自動集約。

## 制約と既存仕様

- 入力ソースルールはアプリ ID と AX 属性の条件で評価される。
- AX の生文字列は永続化しない方針。欄識別に利用する値も安定した属性に限定する。
- 学習統計は既存の設定ルールとは別の端末内データとして管理する。
- 学習機能は初期状態で無効とし、設定画面で有効化された後に記録を始める。
- UI 文言は i18next の全言語パックに追加する。
- 自動切替のフォーカス処理を、学習イベントの処理・保存・候補 UI の表示で待たせない。

## 検討した方法

1. **入力開始時のソースを数える（採用）** — 実際に入力が始まった時点のソースを1回記録する。実装と説明が単純で、明確に合意された方式。訂正入力も初回ソースとして数える限界はあるが、候補は承認制なので許容する。
2. **入力の区切り時点のソースを数える** — 欄を離れた時のソースを記録する。途中で日本語から英語などへ切り替える通常利用を誤認する可能性があるため不採用。
3. **入力キー数や削除数で重み付けする** — 入力内容への介入と複雑さが増え、合意された単純な開始回数の集計に不要なため不採用。

## 合意済みの動作

### 観測と欄の識別

- フォーカスを得ただけでは記録しない。対象欄で実際に入力が始まった時、その時点の `InputSourceId` を1件記録する。
- 観測は `PlatformAppId` と安定した AX 属性から作る欄フィンガープリントに紐づける。
- 安定して識別できない欄は学習しない。異なる欄を誤って統合するより、候補が出ないことを優先する。
- 入力内容および欄のラベルをログに保存しない。

### 保存と判定

- 学習データをルール設定から分離し、端末内に保存する。
- 欄ごとに入力開始時のソース ID を時系列で最大50件保持するリングバッファとする。
- 直近50件のうち同じソースが40件以上になった場合、その欄の候補を適格とする。
- 50件を超えた記録は古い順に置き換え、最新の利用傾向を反映する。
- 学習履歴をリセットできる。ログと候補状態を消去する。
- 学習イベントの集計・保存は自動切替 worker と独立した学習 worker で行う。入力開始 monitor callback はイベント時点の source ID を既存 current-source cache の `try_lock` で読み、snapshot とともに bounded queue へ非ブロッキングで渡す。cache miss / lock contention / queue full はサンプルを破棄する。
- 学習側は共有 input-source gateway mutex を使わない。source 取得、集計、ディスク I/O が自動切替の `select` とロック競合しないようにする。
- 学習ログは学習 worker 内でまとめて保存する。キュー飽和時はイベントを破棄して切替を優先し、保存の遅延・失敗は自動切替へ伝播させない。

### 提示と承認

- 閾値を超えた瞬間には割り込まず、候補を保留する。
- その後、対象欄に次にフォーカスしたとき、入力が始まる前にクイック画面を表示する。
- フォーカス時の自動切替完了後に候補を評価・通知する。候補評価や Quick Set の表示準備は自動切替を待たせない。表示直前に対象 app / focus generation が最新値か確認し、古くなった候補は表示しない。
- 同じ欄に既存の手動ルールがある場合は候補を表示しない。
- 承認されたら、対象アプリと欄の条件、および提案ソースを用いた通常の入力ソースルールとして登録する。
- 見送られた候補は再提案しない。却下状態は欄ごとに学習データとともに保存し、学習履歴リセットで消去する。

## 未確定（実装時に判断）

- OS ごとに「実際に入力が始まった」ことを、入力内容を保存せずに検知する方法。既存実装にはフォーカス監視があるが、キーボード入力開始の共通イベントは確認できていない。
- AX 属性から安定した欄フィンガープリントを生成し、承認時に通常ルールへ変換する具体的方法。
- 学習データファイルの具体的な形式、破損時の復旧方針、および古い未使用フィンガープリントの掃除方法。
- 有効化後に無効化された場合の既存学習履歴の扱い。推奨初期案は記録を停止し、履歴はリセット操作まで保持する。
- 学習キューの容量とまとめ保存の間隔。実装時にメモリ上限を決める。容量到達時はイベントを落とし、送信元や切替 worker をブロックしない。

## 成功条件

- フォーカス移動だけでは学習件数が増えない。
- 実際の入力開始1回につき、識別できる欄で開始時ソースが最大1件記録される。
- 同一欄の直近50件で40件に達する前は候補を提示しない。
- 閾値到達後、次回フォーカス時に入力開始前のクイック画面で承認できる。
- 同じ欄に既存の手動ルールがある場合は学習候補を表示しない。
- 承認後は対応する通常ルールが登録され、見送り後は再提示されない。
- 永続化データに入力文字列・欄ラベルが含まれず、履歴リセットで学習ログと却下状態が消える。
- 学習機能が無効な間は新しい観測を記録しない。
- 学習の保存処理を意図的に遅延させても自動切替が待たずに完了し、queue full / save error が切替結果に影響しない。
- 学習有効時と無効時の同一切替を各30回以上測定し、p50 / p95 を比較する。学習有効時の p95 が無効時より 2 ms または 5%（大きい方）を超えて悪化した場合は、切替 worker に残った学習処理を取り除く。
